# Changelog

## 0.29.3

- The SessionStart hook now updates the plugin itself instead of only announcing a new version (native Claude Code autoUpdate was spiked and rejected: interactive sessions only, after a random 0-10 min delay). When the remote check (every 6h, 1h after a failure) finds a newer version and the plugin is installed through the marketplace, the detached refresher runs `claude plugin marketplace update aaxis-oro`, then `claude plugin update aaxis-oro@aaxis-oro --scope S --json` for the user scope and for the current project's local/project scope (no prompts, `BatchMode` ssh, per-call timeout, lock-guarded, old version directories kept), records `{from,to,ok,ts,scopes}` in `~/.claude/aaxis-oro-update-check.json`, and the next session prints `[aaxis-oro] updated X->Y (restart to apply)` once. No `claude` binary, no marketplace install or a failed update falls back to the manual-upgrade notice. Skipped in subagents. Opt out of the update only: `AAXIS_ORO_NO_AUTO_UPDATE=1`; of everything: `AAXIS_ORO_NO_UPDATE_CHECK=1`.

## 0.29.2

- `aaxis-oro setup sync` enables the Oro plugins (`aaxis-oro` and the six `orocommerce-*`) in `<root>/.claude/settings.local.json` for projects where they are disabled globally: merges `enabledPlugins`, never sets false and warns on an explicit false, skips invalid JSON, adds the file to `.git/info/exclude` when not ignored.

## 0.29.1

- Tighter `solutions/references` (incl. `dialog-forms/*` and `entities/*`): duplicated rules, history and rationale prose removed, one canonical home per rule, no rule or snippet lost; `dialog-forms/README.md` merged into `flow.md`.

## 0.29.0

- Review dispatch brief (goal, range, files, acceptance, skills, model) for every dispatch; the aaxis-reviewer must be told to read `aaxis-oro:solutions`. Explicit models: `model: sonnet` on aaxis-reviewer, `model: opus` on architect-gate, sonnet for the delta reviewer; opus escalation stays the orchestrator's grep. Findings that contradict the user's or ticket's instructions or non-goals are listed as `declined: <why>` before `--fix`. At most 4 refuters per message; no status polling. e2e rule 12: scenarios come from ACs (`@spec:<ID>:AC-n`), red first, final green run by an agent that did not write them. Text tightening, no rule removed: the interceptor/`decorates:` rule is stated in `override-core-service.md` only (pointers elsewhere); e2e `SKILL.md` is a routing index and `checklist.md` cites rule numbers; README, env, setup and solutions de-duplicated.

## 0.28.9

- Leaner review: Blockers only are refuted (Risks self-checked), a small diff (at most 3 files, no risk path) runs only the official lenses, `--fix` uses one delta check, e2e is mandatory only for user-visible behaviour (`task.is_user_visible`), and a replan re-gates only changed plan sections (`task gate-diff`/`gate-record`; SMALL changes need no gate). Rules: `process-rules.md`. Atlas freshness is three-state (fresh / stale-usable / unusable). Stale-usable never blocks and starts one detached incremental rebuild, published as a new `gen/<id>` generation by an atomic `current` symlink flip (readers see one complete generation; failure keeps the old index). Hooks survive a corrupt `index.json`. Also (0.28.8): Fewer repeated full reviews. An approved `review.md` now keeps covering HEAD when the branch's own non-merge commits since its Range head (`git log --first-parent --no-merges`, so merging develop is ignored) changed at most `task.SMALL_DELTA_LINES` (20) production lines (`is_prod`; tests, translations, `.oro-ai/` do not count). A rebase (head not an ancestor) is still stale. Push gate and `task check` use the same `review_state`. `/aaxis-oro:review` runs a single-reviewer DELTA review of `<reviewed head>..HEAD` when the delta exceeds the threshold, refutes only Blockers, and `--fix` does one delta check instead of a rerun. `review-ticket-stop` is now `warn` (a reminder, never blocks); the push gate stays `deny`.

## 0.28.7

- Telemetry dedupe is now per agent. Claude Code also fires PostToolUse inside subagents, and those inputs carry an `agent_id`; the 0.28.6 marker keyed on (session, skill) let a main-session skill call and a subagent's call to the same skill drop each other. The marker is now keyed on (session, `agent_id`, skill): the main session (absent or empty `agent_id`) is one bucket and each subagent its own, so subagent and main-session usage are counted separately, not filtered. Window (120 s), skill_used-only dedupe, the Oro-root gate and the endpoint are unchanged. `agent_id` is used for the key only and is not sent (the wire contract is unchanged).

## 0.28.6

- SessionStart now tells you when a newer plugin version exists: one line (`[aaxis-oro] version X is available (installed Y). Upgrade: ...`) shown to the user, nothing added to the model context, and it never updates anything. Installed version = this copy's `plugin.json`. Latest = the highest of the marketplace clone's `plugin.json` and the cached result of the last remote check; the hook itself never touches the network. When the cache is stale (24h after a success, 1h after a failure) it spawns a fully detached background refresher (same script, `--refresh`, own session, stdio to `/dev/null`) and returns at once; the refresher does a depth-1 `git fetch` of that clone's own origin into a throwaway bare repo (so it reuses the SSH/credential setup Claude Code cloned with) within a ~30s budget and writes the cache atomically, guarded by a lock file with stale-lock expiry. A newer version is announced on the next session after it is found. The repo has no release tags, so `ls-remote --tags` cannot answer. `GIT_TERMINAL_PROMPT=0`, no askpass, SSH `BatchMode` with `ConnectTimeout=10`; any failure is silent and retried after 1h. Cache: `~/.claude/aaxis-oro-update-check.json`. Opt out with `AAXIS_ORO_NO_UPDATE_CHECK=1`. Usage telemetry: the plugin reports usage metadata to AAXIS's ingest endpoint (`POST https://acp-api.aaxis.io/telemetry/events`, contract in `docs/TELEMETRY_API.md`). One hook script, `atlas/hooks/telemetry.py`, registered for SessionStart (all sources), SessionEnd, PostToolUse `Skill` and `Bash`, and UserPromptSubmit; it emits `session_start`, `session_end` (reason, `duration_s` from a start time kept under `~/.claude/aaxis-oro-telemetry/`, `prompt_count`/`tool_count` counted locally from the transcript, omitted when unavailable), `skill_used` (Skill tool calls and typed `/aaxis-oro:*` commands) and `command_used` (`aaxis-oro <subcommand>` run through Bash, subcommand only). Fields and the never-sent list: `docs/TELEMETRY_API.md`. The hook returns at once and prints nothing (no model context); a fully detached sender (own session, stdio to `/dev/null`) gathers the details and POSTs once within 3s with no Origin header and no cookies; any failure drops the event silently, no retry. Telemetry runs only inside an Oro project (the shared `lib/projroot.py` root detection on the hook's `cwd`); outside one nothing is spawned or sent, for every event type. The endpoint is fixed (no environment override). A typed `/aaxis-oro:x` (UserPromptSubmit) and the Skill tool call it triggers (PostToolUse) are one `skill_used`: a per-session, per-skill marker under `~/.claude/aaxis-oro-telemetry/` drops the second within 120 s. README has a Usage telemetry section.

## 0.28.5

- Every project-scoped entry point is now root-gated. Root cause: 0.28.4 gated `env|test|setup|task|review|version|memory|dev refresh` but `atlas` still resolved its root through `find_project_root` (outside a root it exited 1, and an explicit `--project` was never checked, so a non-root directory got a MISSING-filled status with exit 0/2), and `spec coverage|report` took `--root` (default `.`) without any check. `atlas` (queries, `status`, `notes`, `migrate`, `build`, `setup`) uses `projroot.require`: outside a project exit 64 with "no Oro project found from <dir> (need bin/console and composer.lock); cd into one or pass --project", and a non-root `--project` exits 64 "is not an Oro application root". `spec coverage|report` default `--root` to the nearest root above the cwd and gate it the same way; `env switch <name>` refuses a target that is not a root (64). Real roots and worktrees behave as before; hooks still resolve with the non-raising `projroot.find`, so they stay silent with exit 0 outside a project (now covered by a test). `dev lint`, `atlas adoption` and the bare `atlas precommit` no-op operate on no project and stay ungated.

## 0.28.4

- Project root is detected from the fixed Oro application layout, not from where `.oro-ai/` exists. Root cause: 0.28.3 `lib/projroot.py` took the nearest ancestor holding `.oro-ai/config.json`, else the git toplevel, else the cwd, so a stray `.oro-ai/` under `src/` (or any non-Oro directory) could still become the root and receive `.oro-ai/local-env/`. The root is now the nearest ancestor holding `bin/console` and `composer.lock` (the pair atlas and the hooks already used; neither exists below the root, and git worktrees carry both, so each worktree is its own root). With no such ancestor, `aaxis-oro env|test|setup|task|review|version|memory|dev refresh` exit 64 with a clear message and create nothing; there is no cwd fallback. `--project` is kept and must itself be an Oro root. One implementation for every entry point: `atlas`, the hooks, `version`, `review`, `task`, `memory`, `setup`, `env`, `test` and `dev refresh` all call `lib/projroot.py`. The SessionStart version hook now resolves the root (it used the raw cwd for its marker file), the legacy-cleanup hook uses the root for project settings, and the staged pre-commit review is a no-op outside an Oro checkout.

## 0.28.3

- `.stylelintignore` is now the only exclusion list for every linter; the hook no longer builds exclusions from git-ignored and untracked paths. Root cause: the hook turned every ignored path into `--ignore-pattern "dir/**"`, and Oro's stylelint proxy (`oro-stylelint-proxy.mjs`) respawns stylelint with `shell:true` unescaped, so `/bin/sh` expanded the patterns into real directories and stylelint linted about 460k files (OOM). It also wrongly skipped the git-ignored `src/Aaxis/Bundle/AppBundle`. Stylelint now gets no ignore arguments (it reads `.stylelintignore` itself); ESLint gets the entries as quoted `--ignore-pattern` arguments; a negation or unsupported line fails loudly. `precommit.exclude` is retired (sync prints a note). - PHPCS and PHPMD run through a generated, tracked `lint-php.sh` (`.bitbucket/`, `.gitlab/`, `.github/` or `.ci/`) that CI and the hook share, reading `.stylelintignore` and `lint.phpcs-standard` from `.oro-ai/config.json`. `setup sync` fills the standard only when missing (CI's `--standard`, else the old hook's, else PSR12) and creates/refreshes the script; CI keeps its `$HOME` phpcs/phpmd caches, local runs use the git dir. A missing script fails the hook step with a pointer instead of skipping. Removed: the per-command phpcs/phpmd rewriting (`--parallel`, `--cache`, `error_reporting`, PHPMD cache flags) now lives in the script. - Project root: `aaxis-oro env|test|setup|task|review|version|memory` run from a subdirectory resolved the project to the cwd and created `.oro-ai/local-env/` there (for example under `src/.../Tests/`). Root cause: the `--project` defaults were `$PWD`/`os.getcwd()`. They now use `lib/projroot.py`: nearest ancestor holding `.oro-ai/config.json`, else the git toplevel, else the cwd.

## 0.28.2

- The managed hook now replaces CI's PHPMD `--cache`, `--cache-strategy` and `--cache-file` (a `$HOME` path shared by every checkout) with its own per-checkout `<git dir>/phpmd.result-cache.php`, as it already did for phpcs. Root cause: 0.28.1 kept any CI-set `--cache*` flag, so once CI carried them the hook inherited the shared path.

## 0.28.1

- Managed pre-commit hook is faster and quieter. phpcs runs with `--parallel` (nproc, then `getconf _NPROCESSORS_ONLN`, then 1) and `--cache` at `<git dir>/phpcs.cache` (per checkout, nothing to git-ignore, no worktree collisions); CI's own `--parallel`/`--cache` values (a `$HOME` cache shared by every checkout) are replaced in the hook. PHPMD runs as `php -d error_reporting="E_ALL & ~E_DEPRECATED"` (pdepend 2.16.2 prints PHP 8.5 deprecation noise; violations still fail) with `--cache --cache-strategy content --cache-file <git dir>/phpmd.result-cache.php` (assumes PHPMD >= 2.13). Direct tool calls only; wrappers such as `composer run-script` are left as written.
- Repair needs no new mechanism: the hook is rendered, so an installed hook without these flags differs from the render, `setup status` reports `outdated` and `setup sync` rewrites it.

## 0.28.0

- Managed pre-commit hook now matches CI for the tracked tree. Root cause: the steps are CI's whole-tree commands (`phpcs ./src`, `phpmd ./src`, `eslint src`, `yamllint ./src/`) rendered verbatim (`lib/projsetup/precommit.py` `render`), so any file under `src/` that git ignores or excludes (for example a local-only `src/Aaxis/Bundle/AppBundle` in `.git/info/exclude`) was linted locally but never in CI, and could fail the commit. The hook now computes the ignored/excluded/untracked paths at run time and merges them into PHPCS `--ignore`, PHPMD `--exclude`, ESLint/Stylelint `--ignore-pattern`, and feeds YamlLint the tracked YAML files only. New `.oro-ai/config.json` `precommit.exclude` (paths or globs) adds explicit exclusions.
- New opt-out-able `schema-drift` step (`doctrine:schema:update --dump-sql`, local database only, refuses the test stack, noise filtered, incomplete-database message). Root cause of its absence: `steps()` only knew lint/test tools, so the old hand-written hook's drift check had no managed equivalent and vanished on `setup sync`. Opt out with `precommit.skip: ["schema-drift"]`. - Steps are gated by the staged file types (`AAXIS_ORO_PRECOMMIT_ALL=1` or nothing staged runs all). - `setup sync` lists the old hook's steps that have no managed equivalent before replacing it.
- The old buckman hook's exact drift noise filters could not be recovered (its `pre-commit.bak-20261114220450` file no longer exists), so the filters are the ones documented in `env/references/ci-parity.md` and `entity-extend-indexes.md`.

## 0.27.4

- Synced rule blocks trimmed conservatively (`templates/claude-project/process-rules.md`, `review-rules.md`: 5554 to 4945 chars in every session's `CLAUDE_project.md`). Only rationale and the "Prevents ..." clauses moved to `solutions/references/process-rules-rationale.md`; every rule that encodes a non-standard project practice stays in the block, per ETH "Evaluating AGENTS.md" (arXiv 2602.11988: context files add about 20% cost without raising success, keep only non-discoverable rules), Anthropic "Effective context engineering" (2025-09: start minimal, add back what testing shows is needed) and Lulla et al. (arXiv 2601.20404: good context files cut runtime, so keep the anti-wandering rules). Regression guard: `tests/projsetup/rule_inventory.json` lists every command token and key phrase of the pre-trim blocks (all must remain in the blocks or the rationale file; enforcement tokens must stay in the blocks) and pins each block's sha256, so the text is byte-stable (an edit invalidates the prompt-cache prefix and must be deliberate). Run `aaxis-oro setup sync` to refresh projects.
- `/aaxis-oro:review` isolation (arXiv 2603.18740, "When AI Agrees Too Much": PR-description framing made LLM reviewers, Claude Code included, miss vulnerabilities): lenses and refuters judge from the diff, the code and the deterministic check output; PR text, commit messages, ticket text and the author's summary are never passed. The INTENTIONAL block is built from code WHY-comments, READMEs and notes only, labelled untrusted, and honored only after the lens confirms it in code; `plan.md`/`architect-gate.md` go to the plan-drift item only, as untrusted claims. Refuter briefs carry the finding, range and `file:line` only and require an empirical check (run, grep, read callers) over agreement, reporting the check run (arXiv 2604.19049, "Refute-or-Promote"). `agents/aaxis-reviewer.md` states the same rule. The official `review-changes` skill is outside this plugin and still reads the range itself.
- Atlas queries prefilter raw JSONL lines before decoding (`store.read_shard(out_dir, name, terms=None)`): 1.4x-3x faster on buckman (`search kernel` 1101 to 372 ms, `unsafe` 455 to 175 ms), identical output; hook shard reads use it too.
- `aaxis-oro dev refresh` verifies each test target once and hands its sub-steps a private token (`AAXIS_VERIFIED_DIR`): 13 kernel boots down to 3 per refresh. The token must match project and resolved stack; standalone `aaxis-oro test` and `verify` still boot and compare every time.
- SessionStart: one dispatcher (`atlas/hooks/sessionstart.py`) replaces five registered hooks, same matcher semantics and outputs (about 160 ms less per startup).
- `atlas` and `solutions` skill descriptions shortened (about 430 chars less in every session); `atlas/eval/run_eval.py` gained `--plugin-dir` to evaluate one checkout alone.
- `/aaxis-oro:review`: the `aaxis` lens runs on sonnet by default and on opus for high-risk diffs (migrations, ACL/security, workflow transitions, aspect interceptors, `decorates:`), decided by a documented grep.
