Set up this project. Mechanics: `aaxis-oro setup --help`. Idempotent; re-run any time. Never commit in the project; print git commands for the user. Keep output terse.

1. `aaxis-oro setup status`: one line per area (`foundation`, `claude-md`, `project-md`, `rules` (triage pending until applied), `config`, `oro-ai-gitignore`, `pre-commit`, `hook-tools`, `oro-version`, `atlas`, `env`, `memory`); exit 2 = work left; all done: say so, stop.
2. Foundation (skip when `foundation` is `done`; never hand-write CLAUDE_base.md): if `claude-md` is `handwritten`, first `aaxis-oro setup rules` (snapshots the original, writes the rule table) and triage (3) BEFORE the foundation, which rebuilds CLAUDE.md with `--force`. Then invoke `orocommerce-foundation:setup` (services project, version from `oro-version`; `--force` only for a handwritten CLAUDE.md).
3. Triage (handwritten CLAUDE.md only): classify each rule in `.oro-ai/setup/rules.md`: `keep` (inside the `<!-- claude-notes -->` sentinels, the only text `--force` preserves), `move` to CLAUDE_project.md, or `drop` when `aaxis-oro:solutions`/atlas/env/spec already cover it (check first). Plugin-stack rules (atlas-first, interceptor, e2e) drop; project facts and team conventions move. ONE table (id | rule | action | reason) via AskUserQuestion; no writes before the answer. After the foundation, write `{"items":[{"id":1,"action":"keep|move|drop"}]}` to the scratchpad, run `aaxis-oro setup apply-rules --plan <file>`.
4. `aaxis-oro setup sync` (after the foundation, so its Storefront themes section exists): creates CLAUDE_project.md if missing and syncs the `process-rules`, `review-rules`, `plan-rules` blocks (ticket process overrides any command's fast path; extension design cites `aaxis-oro:solutions` + Oro docs; planner Step 5b dispatches `aaxis-oro:architect-gate` as a 4th plan review); creates `.oro-ai/config.json` and `.oro-ai/.gitignore`; installs yamllint user-level if missing; installs the managed pre-commit hook (an unmanaged one is backed up to `pre-commit.bak-<ts>`; relay that path). With files tracked under `.oro-ai` it skips the `.gitignore`: relay the printed `git rm -r --cached` plan with its warning that teammates lose the files on pull, have the user run it, rerun sync. A CLAUDE.md rule saying `.oro-ai` is fully tracked contradicts the standard: put it in the triage table as a rewrite.
5. Print, do not run: the atlas build command from `atlas` (slow; the user decides), `aaxis-oro env setup --project <root>` when `env` is missing (it asks its own questions), `/aaxis-oro:notes-migrate` when `memory` reports unmigrated memories.
6. Finish with `aaxis-oro setup status`; report remaining TODO lines in at most 10 lines.
