# Changelog

## 0.27.4

- Synced rule blocks trimmed conservatively (`templates/claude-project/process-rules.md`, `review-rules.md`: 5554 to 4945 chars in every session's `CLAUDE_project.md`). Only rationale and the "Prevents ..." clauses moved to `solutions/references/process-rules-rationale.md`; every rule that encodes a non-standard project practice stays in the block, per ETH "Evaluating AGENTS.md" (arXiv 2602.11988: context files add about 20% cost without raising success, keep only non-discoverable rules), Anthropic "Effective context engineering" (2025-09: start minimal, add back what testing shows is needed) and Lulla et al. (arXiv 2601.20404: good context files cut runtime, so keep the anti-wandering rules). Regression guard: `tests/projsetup/rule_inventory.json` lists every command token and key phrase of the pre-trim blocks (all must remain in the blocks or the rationale file; enforcement tokens must stay in the blocks) and pins each block's sha256, so the text is byte-stable (an edit invalidates the prompt-cache prefix and must be deliberate). Run `aaxis-oro setup sync` to refresh projects.
- `/aaxis-oro:review` isolation (arXiv 2603.18740, "When AI Agrees Too Much": PR-description framing made LLM reviewers, Claude Code included, miss vulnerabilities): lenses and refuters judge from the diff, the code and the deterministic check output; PR text, commit messages, ticket text and the author's summary are never passed. The INTENTIONAL block is built from code WHY-comments, READMEs and notes only, labelled untrusted, and honored only after the lens confirms it in code; `plan.md`/`architect-gate.md` go to the plan-drift item only, as untrusted claims. Refuter briefs carry the finding, range and `file:line` only and require an empirical check (run, grep, read callers) over agreement, reporting the check run (arXiv 2604.19049, "Refute-or-Promote"). `agents/aaxis-reviewer.md` states the same rule. The official `review-changes` skill is outside this plugin and still reads the range itself.
- Atlas queries prefilter raw JSONL lines before decoding (`store.read_shard(out_dir, name, terms=None)`): 1.4x-3x faster on buckman (`search kernel` 1101 to 372 ms, `unsafe` 455 to 175 ms), identical output; hook shard reads use it too.
- `aaxis-oro dev refresh` verifies each test target once and hands its sub-steps a private token (`AAXIS_VERIFIED_DIR`): 13 kernel boots down to 3 per refresh. The token must match project and resolved stack; standalone `aaxis-oro test` and `verify` still boot and compare every time.
- SessionStart: one dispatcher (`atlas/hooks/sessionstart.py`) replaces five registered hooks, same matcher semantics and outputs (about 160 ms less per startup).
- `atlas` and `solutions` skill descriptions shortened (about 430 chars less in every session); `atlas/eval/run_eval.py` gained `--plugin-dir` to evaluate one checkout alone.
- `/aaxis-oro:review`: the `aaxis` lens runs on sonnet by default and on opus for high-risk diffs (migrations, ACL/security, workflow transitions, aspect interceptors, `decorates:`), decided by a documented grep.

## 0.27.3

- Token/time economy, no behaviour change to any gate: atlas staleness check walks `src/`+`config/` with `scandir` (about 2.3x faster; it runs in the SessionStart, Edit/Write and Bash hooks), `atlas` queries skip the backslash regex for plain strings, the PostToolUse Bash hook skips its post-hoc `git diff` scan for command lines made only of read-only tools, SubagentStart no longer injects the atlas reminder into this plugin's own agents, and the atlas and ticket-process prompt reminders are shorter (the process one no longer repeats the Ticket process block).

## 0.27.2

- `dev refresh`: a `Migrations/` change now also runs `oro:migration:data:load` (new `data-load` step, prod kernel) and reports the fixtures it loaded; `migrate` alone is schema only.
- `env check` / `env repair --only media`: new `sitemap-shadow` item. With a remote public gaufrette adapter, stale files under `public/media/sitemaps/` are served by nginx instead of the generated GridFS sitemap; repair moves them to `moved-aside/`.
- `aaxis-oro test` guard: an empty `database_dsn` from a kernel booted right after a cache clear is retried once, and `live-target.php` falls back to the live connection's parameters instead of reporting an empty DSN.
